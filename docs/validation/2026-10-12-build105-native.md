## Fix boundaries and limits

Build 105 native StartFollowingAvailableAgents selects an entire worker physical range using FindUnavailableWorkers, bypassing the old available-worker filter. Family exclusions now apply there and to available/reassignable/direct follower selection. Deferred native flow updates enter the owning commander's context; nested host callbacks temporarily enter the native host context. Native follow execution remains in the game.

The GUI already used the per-owner FamilyStatus -> FamilyHud path. The divergent runtime check confirms that path instead of adding a second HUD writer. Native camera, HUD rendering, targeting and cancellation continue to execute.

This validates the recorded scenarios, not every mechanic or every unknown mod. Multi-client/late-join adapter delivery, refusals and required-addon rejection have automated Core coverage; a complete manual gameplay matrix, arbitrary custom assets, every native tool, long sessions and arbitrary third-party mod combinations were not exercised here. New mechanics that bypass covered native mutation entry points require explicit adapters. Unsupported custom code/assets are not synthesized on missing peers.

Cold or unfocused windowed startup exceeded the bounded fixture wait in one repeat run; that report is blocked/timed out and is not counted as a passing scenario. The final batch pair retained active native simulation and passed. The runtime harness is opt-in and is excluded from the player package.
